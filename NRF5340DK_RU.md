# MiniMic Streamer на nRF5340 DK — запуск и управление

## Что готово

Прошивка перенесена на **обычную nRF5340 DK / PCA10095** со **встроенным радио**.
Внешний nRF24L01+ PA+LNA, Pico и соединительные провода не нужны.
Текущая сборка — **0.1.14**. Оба ядра компилируются, 19 проверок ARM-кода в эмуляторе проходят.
На реальной DK проверены запись и readback обоих ядер, CDC и появление выхода
Windows **«Динамики (MiniMic Audio)»**, приём USB-аудиопотока цифровой тишины и
команды OFF/ON/MUTE/UNMUTE. На этой плате работает один кабель в J3 при SW9 в VDD.
**В 0.1.12 сопряжение с Nucleus 7 подтверждено:** получено восемь пакетов `0x16`
с адресом платы. В диагностике использовались +3 dBm и перебор задержек; первый
ответ-подтверждение пришёл после передачи с фактическим стартом на 6001 мкс.
См. [лог успешного сопряжения](diagnostics/nucleus7-0.1.12/README.md).
**В 0.1.14 звук появился после выбора Mini Microphone в приложении Nucleus**,
но пользователь отмечает плохое качество и длительные пропадания. USB-аудиопоток
поступает на плату без пропусков и ошибок. В 0.1.13 +3 dBm включено также для аудио, проверен
ненулевой PCM и меняющиеся данные кодека. В 0.1.14 пара пакетов передаётся без
повторного разгона RADIO; на плате проверены период 6144 мкс и пауза 17–19 мкс
вместо прежних 157–158 мкс при включённой трассировке. Стабильность звука не подтверждена;
см. [результат проверки аудио](diagnostics/nucleus7-audio-0.1.14/README.md).
По умолчанию сопряжение использует +3 dBm и тот же перебор шести задержек,
который дал подтверждение в 0.1.12. Обычная передача также настроена на +3 dBm.
Светодиоды сами по себе не подтверждают сопряжение.
Полный лог успешного сопряжения — `dist/nucleus7-pairing-0.1.12-success.log`, архив —
`dist/nucleus7-pairing-0.1.12-success.zip` (эти файлы остаются локально).
В GitHub доступна [копия без серийного номера](diagnostics/nucleus7-0.1.12/README.md).
Для сравнения сохранена [неудачная попытка 0.1.11](diagnostics/nucleus7-0.1.11/README.md):
42 принятых пакета, 42 ответа, ни одного подтверждения. Проверки эмулятора — в `TESTS.json`.
Ни успешная компиляция, ни эмулятор не доказывают совместимость с Nucleus 7.

В 0.1.11 добавлен полный лог RX/TX: все 32 байта, адреса, регистры RADIO и
метки READY/ADDRESS/END, захваченные аппаратно таймером сетевого ядра через DPPI.
Лог сохраняет также неизвестные пакеты и пакеты с неверной CRC. Он охватывает
настроенный канал и адрес приёма, а не весь эфир. Через J2 его снимает
`tools/capture_rf_swd.py`; отладочное разрешение радио снимается по окончании записи.

В 0.1.1 исправлено объединение аудиоинтерфейсов (IAD), устранившее Windows Code 10.
В 0.1.2 удалён пустой Feature Unit: он создавал разорванный аудиотракт Windows и
не позволял появиться выходу звука. В 0.1.3 исправлен радиоформат: исходные
`EN_AA=0` и `ARC=0` означают ShockBurst **без** 9-битного ESB PCF.
В 0.1.4 исправлен порядок байтов радиоадреса при переходе от nRF24 SPI к
встроенному RADIO частично (выбор prefix). В 0.1.6 исправлен также порядок
байтов BASE: RADIO передаёт младший из используемых байтов первым. Проверка
эфирного адреса теперь учитывает это отдельно от функции преобразования.
В 0.1.3 на реальной DK получены beacons Nucleus 7 с правильной
CRC и проверен USB-аудиопоток цифровой тишины; подтверждения сопряжения ещё не было.
В 0.1.4 подтверждения также не получено после перезапуска Nucleus 7. Версия 0.1.5
добавляет диагностический перебор задержки ответа (3,8–7,8 мс вокруг исходных
5,8 мс) и счётчики `replies` / `delay_us`. Это проверка временного окна приёмника,
а не подтверждение совместимости Nucleus 7.
В 0.1.6 исправления адреса также не привели к подтверждению: проверено полное
окно с 82 ответами, а также дополнительные задержки через CDC. Чтобы установить
причину, нужно сравнить реальный радиообмен с работающим передатчиком для Nucleus 7
или проверить оба радионаправления независимым приёмником. Такого сравнения пока нет.

## Первая прошивка

1. Установи Windows-пакет [SEGGER J-Link Software and Documentation Pack](https://www.segger.com/downloads/jlink/),
   включая USB-драйвер. Дополнительный программатор покупать не нужно: J-Link уже есть на DK.
2. Подключи кабель с передачей данных к **J2 / DEBUG USB / J-Link**. Поставь
   **SW8 / nRF POWER в ON**, **SW9 / nRF POWER SOURCE в VDD**. Остальные переключатели
   оставь в заводских положениях. Такой вариант с питанием через J2 удобен для первого запуска.
3. Открой PowerShell в папке проекта и выполни:

   ```powershell
   cd C:\Cochlear\minimic-streamer-nrf5340dk
   .\tools\nrfutil.ps1 install device
   .\tools\nrfutil.ps1 device list
   ```

   Скрипт загружает nRF Util с официального сервера Nordic и хранит его внутри
   `build/`, без изменения системного PATH. На этой машине модуль `device` уже подготовлен.
   Если PowerShell блокирует запуск `.ps1`, открой для этой работы отдельное окно:
   `powershell -NoProfile -ExecutionPolicy Bypass`, затем повтори команды.
4. Скопируй серийный номер J-Link из списка. Выполни команду, заменив `123456789`
   своим номером:

   ```powershell
   .\tools\flash-nrf5340.ps1 -SerialNumber 123456789
   ```

   **Она заменяет старую прошивку и настройки во flash обоих ядер DK.** Сначала
   записывается и проверяется сетевое ядро, затем основное; после этого плата перезапускается.
   Если программа сообщает о защите памяти, не выполняй случайные команды `recover`:
   сохрани текст ошибки для разбора.
5. **Переставь этот же кабель из J2 в J3 / nRF USB**. Второй кабель покупать
   не обязательно. На проверенной DK питание и USB работают через один J3
   при SW9 в VDD. В Windows выход называется **«Динамики (MiniMic Audio)»**,
   а общее USB-устройство — **MiniMic Streamer nRF5340**. Через J2 звук не поступает.

Расположение разъёмов и питание описаны в официальном
[руководстве nRF5340 DK](https://docs.nordicsemi.com/r/bundle/ug_nrf5340_dk/).
При одном кабеле используй J2 только для обновления, затем переставляй его
в J3 для звука. Одновременное подключение двух кабелей удобно для отладки,
но не является обязательным условием работы.

## Первое сопряжение со слуховым процессором

Это протокол MiniMic, **не Bluetooth и не ASHA**. В списке Bluetooth Windows
добавлять плату не нужно. Имя процессора **AS Hearing Device** менять не требуется.

1. Выключи оригинальный MiniMic и другие передатчики с этой же прошивкой рядом.
2. Перед каждой новой диагностической попыткой сними наружный Nucleus 7 с катушкой
   и выключи его. Удерживай **Button 1 примерно 1,5 секунды**. **LED3 быстро мигает**:
   открыто окно сопряжения на **30 секунд**. Звук в это время не передаётся.
3. Сразу включи процессор и оставь снятым рядом с платой до конца окна: к концу
   мигания он должен быть включён не меньше 10 секунд. Для каждой следующей
   диагностической попытки снова выключай и включай его. Перезапуск и выдержка
   выполнены в последней проверке, но сами по себе не устранили отсутствие сопряжения.
4. На каждое подтверждение LED3 загорается примерно на секунду; по окончании
   успешного окна — на три секунды. Если подтверждений не было, LED4 мигает
   около трёх секунд. Долгое нажатие Button 1 ещё раз отменяет сопряжение.
5. Выбери **«Динамики (MiniMic Audio)»** в качестве вывода звука в Windows или
   конкретном приложении. Начни с небольшой громкости и короткого звука.
   Если процессор требует включить режим аксессуара/стриминга, выбери его обычным
   для этого процессора способом.

Для Nucleus 7 после подтверждённого сопряжения удерживай кнопку процессора две
секунды и отпускай. **Первый выбранный источник может быть телекатушкой**, если
она настроена. Следующие такие длинные нажатия перебирают сохранённые аксессуары;
между ними подожди несколько секунд. Короткое нажатие выключает стриминг.
См. [руководство Cochlear, раздел Streaming audio from True Wireless devices](https://assets.cochlear.com/api/public/content/FUN2927-Nucleus-7-Welcome-Guide.pdf).

По исходному проекту процессор запоминает передатчик; каждый раз после отключения
USB заново сопрягать его не требуется. Плата использует постоянный адрес
`12 34 56 78`, поэтому ей не нужно хранить список процессоров во flash.
Счётчик `paired` в диагностике относится к последнему окну сопряжения и сбрасывается
при перезапуске; ноль после включения сам по себе не означает потерю сохранённого
сопряжения в процессоре.

В исходнике работоспособность проверялась автором с **Nucleus 8 на Pico 2 W + nRF24L01+**.
Этот результат не подтверждает работу нового порта или других моделей. Сохранились
ограничения исходного протокола: один фиксированный адрес и сопряжение в слот 1.
Для возврата к оригинальному MiniMic может потребоваться снова сопрячь процессор с ним.

## Повседневное управление

| Действие | Как сделать | Что происходит |
|---|---|---|
| Подать / убрать питание | SW8 ON / OFF | Включает / выключает nRF5340. Прошивка остаётся во flash |
| Подключить звук к ПК | Кабель в J3, выбрать MiniMic в выводе звука | USB-звуковая карта принимает звук |
| Остановить радиопередачу | Коротко Button 2 | LED2 гаснет, передача всех радиопакетов прекращается |
| Возобновить радиопередачу | Ещё раз коротко Button 2 | LED2 загорается, передача возобновляется без нового сопряжения |
| Быстро заглушить звук | Коротко Button 3 | LED4 горит постоянно; по радио идёт тишина для сохранения синхронизации |
| Вернуть звук | Ещё раз коротко Button 3 | LED4 гаснет |
| Сопряжение / отмена | Button 1 удерживать 1,5 секунды | Открывает / закрывает окно сопряжения |
| Вывести состояние | Коротко Button 4 | Пишет строку состояния в открытый MiniMic Control |

**LED1** горит, когда USB J3 настроен компьютером и не находится в suspend.
**LED2** показывает работу местного передатчика, а не подтверждённое подключение
процессора: у аудиопакетов исходного протокола нет ACK.
**LED3** относится к сопряжению. **LED4** горит при mute, мигает при ошибке ядра/радио
или коротко после неудачного окна сопряжения. Постоянный mute имеет приоритет над миганием.

Порядок на каждый день: включить SW8 → подключить J3 → выбрать MiniMic в выводе звука.
После каждого включения передача разрешена, mute выключен. При отсутствии звука
плата посылает пакеты тишины, как исходный Pico. Чтобы совсем прекратить передачу,
нажми Button 2. Выбор других динамиков Windows сам по себе не отключает радио.
Отключение J3 или USB-suspend останавливает радио; после возвращения USB оно
возобновляется, если ты не отключил его кнопкой. Ручные ON/OFF и MUTE действуют
до перезапуска. При открытии сопряжения передача включается автоматически.

Выключение передачи не стирает сопряжение и не отправляет команду удаления
аксессуара процессору. Это остановка радиолинка; точное поведение процессора
после потери сигнала зависит от его модели. Удаление или замена сопряжения —
отдельное действие на стороне процессора/оригинального аксессуара.

## Управление с компьютера

Посмотреть COM-порт:

```powershell
.\tools\control-nrf5340.ps1
```

Открывай порт **MiniMic Control**, относящийся к USB `VID_CAFE&PID_5340`;
COM-порт от J-Link на J2 для этих команд не подходит. Пример для COM7:

```powershell
.\tools\control-nrf5340.ps1 -Port COM7 -Command STATUS
.\tools\control-nrf5340.ps1 -Port COM7 -Command PAIR
.\tools\control-nrf5340.ps1 -Port COM7 -Command CANCEL
.\tools\control-nrf5340.ps1 -Port COM7 -Command OFF
.\tools\control-nrf5340.ps1 -Port COM7 -Command ON
.\tools\control-nrf5340.ps1 -Port COM7 -Command MUTE
.\tools\control-nrf5340.ps1 -Port COM7 -Command UNMUTE
.\tools\control-nrf5340.ps1 -Port COM7 -TxPowerDbm 3 -Command STATUS
.\tools\control-nrf5340.ps1 -Port COM7 -TraceAudioFrames 4 -Command STATUS
.\tools\control-nrf5340.ps1 -Port COM7 -AudioGapUs 1000 -Command STATUS
.\tools\control-nrf5340.ps1 -Port COM7 -Watch
```

Команды можно отправлять и обычным serial-терминалом: ASCII, окончание строки LF,
115200 бод. `HELP` выводит список; `REBOOT` перезапускает плату.
`TXPOWER 0/3` меняет мощность обычной передачи. `AUDIOGAP 0..300` задаёт паузу
между пакетами слота без нового TXEN; `AUDIOGAP 1000` включает прежний раздельный
разгон каждого пакета. По умолчанию после перезапуска: +3 dBm и AUDIOGAP 0.
`TRACEAUDIO 1..16` записывает ограниченное число кадров, затем трассировка аудио
останавливается. У второго пакета пачки нет нового READY: `kind=7` и
`start_source=START_TASK` помечают программную метку перед START. ADDRESS/END
всегда фиксируются аппаратно; `kind=5` использует аппаратную метку READY.
Скорость 1200 бод больше не вызывает сброс. USB-загрузчика и Pico BOOTSEL здесь нет:
обновление выполняется через встроенный J-Link.

Диагностика раз в секунду: `net=ready`, `usb=1`, `enabled=1`, `tx_active=1` означают,
что местные USB и передатчик работают. `mode=audio` означает открытый USB-аудиопоток,
а не обязательно ненулевой звук. `tx` должен расти примерно на 163 кадра в секунду;
в одном кадре пять радиопакетов. `under` растёт и при отсутствии воспроизведения.
`pcm_peak` показывает модуль входных 16-битных PCM-отсчётов последнего блока,
`encoded` — число выданных кодеком кадров. Ненулевой `pcm_peak` подтверждает входной
сигнал, но не его приём процессором.
`late` и `faults` должны оставаться нулевыми. `paired` и `beacons` помогают разобрать
сопряжение; они не являются непрерывной проверкой присутствия процессора.
В версиях 0.1.1+ `rx_addr` считает совпадения радиоадреса, `crc_ok` / `crc_bad` —
принятые пакеты с правильной / неправильной CRC, `rx_other` — правильные по CRC
пакеты, не распознанные как beacon. Эти счётчики накопительные с момента включения.

Сохранены бинарные команды исходника `5A C3 P/R/M/m/L/l` и подача 84-байтных кадров
после `5A A5`. Изменение адреса/таблицы каналов через `A/H` не поддерживается:
известная hop-таблица соответствует только адресу `12345678`.
`5A C3 B` возвращает сообщение об отсутствии USB-загрузчика.

Для внешней антенны 2,4 ГГц требуется согласованный переходник для **J1 / SWF
Murata MM8130-2600**; обычный SMA или u.FL напрямую не подходит. Подключение
совместимого кабеля отключает печатную антенну. J5 относится к NFC и не является
разъёмом радиолинка MiniMic. См. [описание RF-разъёма Nordic](https://docs.nordicsemi.com/r/bundle/ug_nrf5340_dk/page/ug/dk/hw_rf_measure.html).

## Если не заработало

- `device list` пуст или сообщает `JLinkARM DLL not found`: установи J-Link,
  проверь кабель J2 с передачей данных и SW8/SW9.
- J-Link виден, а звуковой карты нет: переставь имеющийся кабель в J3; проверь LED1.
  Проверь, что загружены **оба** новых образа, и перезапусти питание.
- Windows показывает Code 10 или нет выхода «Динамики (MiniMic Audio)»: обнови
  прошивку до 0.1.6 или новее. В ранних версиях были ошибки USB-дескрипторов.
- В статусе `net=fault`: выключи питание и повтори загрузку двух образов.
- `beacons=0` при сопряжении: перезапусти процессор именно внутри 30-секундного окна,
  начни вблизи платы. Если не помогает, требуется аппаратная проверка пакетов/радио.
- Сопряжение подтверждено, но звука нет: проверь вывод Windows, режим аксессуара
  процессора, LED2 и mute/LED4. Сохрани статус командой `-Watch`.
- На старой схеме PA+LNA усиливал радио. У DK его нет; здесь используется
  встроенная PCB-антенна и **0 dBm**. Прежнюю дальность обещать нельзя.

## Сборка из исходников

На этой машине уже выполнена:

```powershell
.\tools\build-nrf5340.ps1
```

Нужны Git, CMake 3.20+, Ninja, Python 3 и Arm GNU Toolchain. Скрипт умеет находить
компилятор и Ninja в установленном Pico SDK, но **прошивка не использует Pico SDK**.
Если автоматический поиск не сработал:

```powershell
.\tools\build-nrf5340.ps1 -ToolchainBin 'C:\path\to\arm-gnu-toolchain\bin' -Ninja 'C:\path\to\ninja.exe'
```

Зафиксированы TinyUSB 0.20.0, nrfx 3.14.0 и CMSIS 5.9.0; точные commits указаны
в скрипте и `BUILD.json`. Основное ядро работает на 128 MHz с аппаратной FPU,
сетевое — на 64 MHz без FPU. Кодек из `codec/encoder.c` сохранён. Ядра обмениваются
кадрами через выделенную RAM `0x20070000`; эта область исключена из памяти линкера
основного ядра. USB использует единственную доступную изохронную пару nRF USBD:
OUT `0x08`, feedback IN `0x88`. CDC использует отдельные endpoints.

Проверки собранного ARM-кода:

```powershell
python -m pip install --target build/test-deps -r tests/requirements.txt
python tests/verify_firmware.py
```

Проверяются полный 48-кадровый цикл каналов, пять пакетов на кадр и их содержимое,
тишина при mute, отключение/включение, сброс очереди, отмена/таймаут сопряжения,
ответ и подтверждение сопряжения, перебор и фиксация задержки ответа,
переполнение микросекундного таймера, USB-дескрипторы
из ELF и объединение HEX. TIMER/RADIO в этих проверках моделируются: реальные
электрические сигналы, эфир, USB-драйвер Windows и воспроизведение ими не проверяются.
Предупреждение GNU ld о RWX-сегменте относится к ELF-разметке штатного Nordic
`nrf_common.ld`; переполнений flash/RAM нет.

Для окончательной проверки на железе нужны: загрузка и USB-enumeration, пробное
сопряжение, короткое воспроизведение с небольшой громкостью, кнопки ON/OFF/MUTE,
отключение и возврат USB, сон/пробуждение ПК, затем длительное воспроизведение
с контролем `late/faults` и дальности.
